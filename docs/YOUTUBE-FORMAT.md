# YouTubeのショート候補を分ける（v0.8）

「YouTubeの種類」で、すべて・通常動画候補・ショート候補・未判定を選び、「検索」を押します。
再生時間とタイトル・説明欄のハッシュタグから推定する機能です。YouTube公式の分類ではありません。
検索対象が「両方」のときも、この条件はYouTubeだけに適用し、ニコニコはそのまま表示します。
ニコニコのみを選ぶと種類の選択欄は無効になります。

## 判定する内容

| 取得した情報 | 推定分類 |
| --- | --- |
| 3分以内で、対象のハッシュタグあり | ショート候補 |
| 3分1秒を超え、対象のハッシュタグなし | 通常動画候補 |
| 3分以内だがハッシュタグなし | 未判定 |
| 3分を超えるがハッシュタグあり | 未判定（時間と表記が矛盾） |
| 3分を超え3分1秒以内 | 未判定（APIの時間誤差を考慮） |
| 再生時間が不明・不正、詳細取得に失敗 | 未判定 |

対象は独立した `#shorts`、`#youtubeshorts`、`#ショート`、`#ショート動画` です。
大文字小文字・全角半角の違いは統一します。`shorts`という普通の単語や`#shortstory`は対象にしません。
APIが返す省略前の説明欄を確認します。説明欄そのものは画面や履歴へ保存しません。
タイトルが「短い動画」でも、時間だけではショート候補にしません。

ハッシュタグは投稿者が付ける表記なので、誤用や付け忘れがあります。
タグのない本物のShortsは未判定になり、誤ったタグのある短い通常動画はショート候補になることがあります。
縦横比・投稿時期などを含むYouTubeの正式な分類を再現したものではありません。
カードには再生時間、推定分類、判断の根拠を表示します。未判定も一覧から選んで確認できます。
固定一覧の動画に再生時間が保存されていない場合も、未判定として表示します。

## 検索・もっと見るとの関係

- 通常は各サイト最大6本、履歴補正が有効なら最大18本を取得した後、そのページのYouTubeを種類で絞ります。
- 表示が6本未満や0本になることがあります。件数を埋めるために裏で何ページも検索しません。
- 0本でも外部APIに次のページがあれば「もっと見る」を表示します。
- 選択欄を変更しただけでは現在の結果は変わりません。「検索」で新しく実行します。
- 「もっと見る」や再試行は、最初に実行した種類・並び順・投稿期間を維持します。
- 履歴による補正は、種類で絞った候補の中で行います。
- 「固定の一覧に戻す」で種類も「すべて」に戻ります。

「直近に取得したYouTubeの内訳」は、直近の取得ページを絞る前の件数です。
検索結果全体の総数や、表示中の累計件数とは異なります。

## バックエンドの流れ

1. `search.py` が通常の検索条件で外部APIを呼びます。
2. `metadata.py` が `videos.list` の `snippet,statistics,contentDetails` を1回でまとめて取得します。
3. `youtube_format.py` が `contentDetails.duration` を秒へ変換し、全文タイトル・説明欄から推定します。
4. 分類を含む元の候補を短期キャッシュへ保存します。
5. 返すときだけ種類で絞り込みます。元の候補を消さないため、同じページの種類変更に再利用できます。
6. 続き情報には種類も含めて照合します。違う種類への途中流用は410で拒否します。

追加する検索パラメーターは `youtube_format=all|regular|shorts|unknown`、省略時は `all` です。
動画に `duration_seconds`（秒・未取得null）、`youtube_format`（推定分類・ニコニコnull）、`format_reason`（根拠）を追加します。
検索応答の `sources.youtube.format_counts` は3分類の件数、`fetched_count` は絞る前の件数です。
`sources.youtube.count` は絞った後の件数です。

YouTube検索APIの `videoDuration=short` は「4分未満」であり、Shorts指定ではないため使いません。
