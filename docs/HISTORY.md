# 視聴履歴を使う検索（v0.7）

YouTubeの過去の視聴履歴を取り込み、このアプリ内での新しい再生記録と合わせて検索へ反映します。
YouTube公式の個人向け検索順位を取得する機能ではありません。

## 初めて使うとき

1. 新しいソースでサーバーを起動し、`http://127.0.0.1:8000/` を開きます。
2. 「視聴履歴を管理」を開きます。
3. 過去の履歴を使う場合は、下記のTakeoutファイルを選び「選んだ履歴を取り込む」を押します。
4. 今後の再生を記録する場合は「アプリ内のYouTube再生を履歴に記録する」をオンにします。
5. 検索欄の「履歴を検索に反映」をオンにし、並び順を「標準」にして検索します。

履歴の記録と検索への反映は別の設定です。どちらも初期値はオフです。
反映設定を変更しただけでは表示中の結果は変わりません。「検索」で実行します。
設定と本人識別キーは、このブラウザのサイト保存領域に残ります。

## YouTubeの過去の履歴を用意する

1. [Google Takeout](https://takeout.google.com/)を開き、自分のGoogleアカウントで操作します。
2. 対象を「YouTubeとYouTube Music」に絞ります。
3. 含めるデータで「履歴」を選び、履歴の形式を **JSON** にします。画面上の名称は変更される場合があります。
4. エクスポートを作成し、Google側の準備が終わったらダウンロードします。
5. ZIPを展開し、`history/watch-history.json` に相当する視聴履歴ファイルを選びます。
6. アプリの取込結果で、追加・重複・対象外の件数を確認します。

JSONファイルは10MB、入力配列は10万件まで。保存は新しい5000件までです。
HTML・ZIP・検索履歴JSONは取込対象ではありません。UTF-8（BOMあり・なし）に対応します。
同じ動画IDと視聴日時の組み合わせは再取り込みしても重複しません。
広告、動画リンクのない記録、不正な日時などは対象外として数えます。
Takeoutの記録から視聴時間・完視聴・好き嫌いまでは分かりません。
YouTube側で削除済み・保存停止中だった履歴を復元する機能もありません。
取込は手動であり、YouTube本体との自動同期は行いません。

## 今後の再生を記録する

### YouTube

カード下の「アプリ内で再生」を押し、公式プレイヤーの再生ボタンを押します。
記録設定がオンで、画面が表示されている間の再生が合計10秒以上になったら1件保存します。
停止・バッファリング・シーク・非表示の経過時間を、そのまま視聴時間に加算しません。
保存する秒数は記録成立時点の値で、動画全体の最終視聴時間ではありません。

埋込禁止や削除などで再生できないときは「YouTubeで見る」を使えます。
子供向け指定、または指定を確認できない動画は自動記録しません。
短い動画を10秒未満で見終わった場合も記録しません。
外部サイト・YouTubeアプリで見た分は、このアプリのプレイヤーでは観測できません。

### ニコニコ

元サイトで視聴後、カードの「見たと記録」を押します。
これは本人が申告した履歴です。外部サイトでの再生時間を自動で測ってはいません。

## 検索への反映

通常検索は各サイト最大6本。履歴があり「標準＋履歴を検索に反映」の場合は各サイト最大18本です。
履歴の補正で下位になったことだけを理由に動画を捨てることはありません。
v0.8でYouTubeの種類を指定した場合は、その条件で絞った候補の中で順位を補正します。

1. 入力された検索語と投稿期間で、各サイトのAPIへ検索します。
2. 最新1000件までの履歴から、話題と投稿者の傾向をまとめます。
3. 新しい履歴ほど重く、同じ動画の繰り返しは1本として扱います。
4. 各サイトの元の順位に、履歴との一致を加味して候補内を並べ替えます。
5. YouTube・ニコニコを交互に表示します。

日本語は2～3文字のまとまり、英数字は単語で一致を調べる簡易方式です。
AIによる動画内容の理解ではなく、意味の取り違えや偶然の文字一致も起こり得ます。
再生数や高評価数を独自の人気スコアに変換する処理はありません。
理由表示はこのアプリの履歴に基づき、YouTubeやニコニコが提示した評価ではありません。

「新しい順」「再生数が多い順」を選んだ場合は、その指定を優先して補正しません。
取得した候補にない動画を見つけ出す機能ではありません。
「もっと見る」は押した時点で次の候補を取得し、そのページ内で補正します。
全ページを取得してから全体を並べ直すものではありません。
ページ途中で履歴が増えても、同じ検索の続きでは開始時点の好みを維持します。
履歴を削除した場合は、その履歴を使った続きも無効になります。

## 保存場所と削除

- サーバーの `backend/data/private/history.sqlite3` に保存します。SQLiteはPython標準機能なので追加インストールは不要です。
- `HISTORY_DB_PATH` 環境変数で保存先を変更できます。データベースと実履歴JSONはGitHubへ含めません。
- 取込履歴は削除するまで、最新5000件の範囲で保存します。
- アプリ再生・手動記録は30日経過後、履歴読込時に削除します。
- 「このアプリに保存した自分の履歴をすべて削除する」をチェックし「履歴を削除」で削除できます。
- YouTube本体や手元のTakeoutファイルは削除しません。
- 通常検索や外部APIへ履歴・本人識別キーを送信しません。ユーザーが押した埋込プレイヤー自体はYouTubeへ通信します。

ログインは未実装です。同じブラウザ・同じURLの保存キーで本人を区別します。
ブラウザのサイトデータを消すとキーも消え、元の履歴へアクセスできなくなります。先にアプリで履歴を削除してください。
`localhost` と `127.0.0.1`、異なるポート、異なるブラウザは別の保存領域です。
SQLiteファイルを管理するサーバー管理者は保存内容へアクセスできます。
現在の起動手順は自分のPC内の利用を想定しています。インターネット公開時はアカウント管理・HTTPS・保存管理を別途整える必要があります。

## バックエンド担当向け

| 窓口 | 内容 |
| --- | --- |
| `GET /api/history` | 本人の総件数と最新100件 |
| `POST /api/history/import` | Takeout JSON配列を本文で送信 |
| `POST /api/history/manual` | ニコニコを見たという本人の記録 |
| `GET /api/playback/youtube/{id}` | 埋込可否・自動記録可否・短期の記録許可 |
| `POST /api/history/playback` | 記録許可と10秒以上の再生時間を送信 |
| `DELETE /api/history` | 本人の履歴と個人向け検索の続き情報を削除 |
| `GET /api/search?personalized=true` | 本人の履歴を使う検索 |

履歴の窓口は `X-History-Token` ヘッダーが必要です。ブラウザで生成した32バイトの乱数を64桁の16進数で送ります。
DBにはキーそのものを保存せず、SHA-256で変換した値を利用します。値をURLやログへ出さないでください。
これはアカウント認証の代替となる簡易な端末識別です。キーを知る人は本人の履歴へアクセスできるため、共有しないでください。
フロントはFastAPIと同じオリジンから配信して使います。別ポートの画面に履歴の書込権限は付けていません。

`history.py` が取込と保存、`history_api.py` がHTTP窓口、`personalization.py` が検索補正を担当します。
通常検索のキャッシュは共有しても、本人の履歴と補正済み結果は共有しません。
履歴を使う続き情報は30分・最大256件のメモリ内保存で、再起動すると無効になります。
